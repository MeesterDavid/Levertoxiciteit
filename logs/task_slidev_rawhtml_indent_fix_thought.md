- **Date / Time:** 2026-11-05T15:40:00+01:00

## 1. Analysis & Problem Statement
- **What is being asked?**
  - The user reports: `public/slide1_pitch_preview.html` (standalone HTML generated by `generate_slide1_assets.py`) looks correct, but the *Slidev* version shows the raw HTML source as text on screen.
  - Interpretation: the Markdown → HTML pipeline of Slidev is mangling slide 1; the standalone preview is fine because it never passes through a Markdown parser.
- **Root cause (verified, not assumed):**
  - Slidev 53 renders each slide body with `markdown-exit` (markdown-it-compatible) and options `{ quotes, html: true, xhtmlOut: true, linkify: true }` — see `slides/node_modules/@slidev/cli/dist/serve-CjzN30uY.mjs:2566`.
  - CommonMark rule: after a blank line, a line indented by **>= 4 spaces** starts an *indented code block*.
  - In `slides/slides.md`, lines 13–165 (the whole slide-1 body) are indented 2–14 spaces. Lines 15–25 (indent 2) are still raw HTML blocks (<= 3 spaces allowed), which is why the header/eyebrow/title rendered correctly. From line 27 (`    <!-- LEFT COLUMN: DE CONTEXT -->`, indent 4) onward, **128 of 153 lines** are indented >= 4 spaces, so they form ONE giant indented code block that only terminates at line 167 (`<style>`, column 0).
  - Consequence: the entire two-panel layout is escaped into `<pre><code>` (`&lt;div ...&gt;`, `&amp;amp;`), while the CSS in `<style>` still applies — exactly matching the screenshot.
- **Pitfalls / boundary conditions:**
  - De-indenting by hand risks typos in 153 lines containing `·`, `&amp;`, `—` and Dutch text → do the whitespace transform mechanically and verify with `git diff`.
  - Any future Markdown formatter (Prettier format-on-save) re-indents embedded HTML and would reintroduce the bug → collapse blank lines inside the wrapper so no line inside the slide body can be re-interpreted as Markdown, and leave a guard comment.
  - `slidev build` output (`dist/`) is git-ignored; the dev script is `slidev --open` (headless-hostile) → verify with `pnpm exec slidev --port 3030` instead.
  - Only SVG placeholders exist in `public/`; the slide references `*.png` with an inline `onerror` PNG→SVG fallback → this inline handler must be verified in a real browser (Vue keeps non-`on[A-Z]` attributes as static attributes).

## 2. Methodological & Scientific Considerations
- **Why this approach:** the defect is purely a serialization/whitespace issue in the presentation layer, not a content or modelling issue. The minimal, auditable fix is to normalise the leading whitespace of the raw HTML block (flush-left) and remove the blank lines inside the wrapper so the body is one contiguous raw-HTML block.
- **Why not disable indented code blocks globally** (`markdownSetup(md => md.disable('code'))`): that would break every 4-space-indented code block in all future slides — a regression traded for a symptom.
- **Why not a Vue component (`Slide1Pitch.vue`):** architecturally cleaner and formatter-proof, but it relocates the entire slide out of `slides.md` and requires splitting the global `.slidev-layout` style override from component-scoped rules. For a 2-slide pitch this is unnecessary churn; the contiguous-raw-HTML variant already removes the failure mode.
- **Research-proposal alignment:** unchanged — this is the pitch deck for *Multimodal en Multiscale AI in de Toxicologie*; the content (qAOP / Physiological Maps / CSD tissue-level emergence) is preserved byte-for-byte, only indentation changes.

### 4.1 Mechanical de-indent (lines 13–165) — whitespace-only, content-preserving
```bash
cd slides
cp slides.md /tmp/slides.md.before_fix
awk 'NR>=13 && NR<=165 { if ($0 ~ /^[[:space:]]*$/) next; sub(/^[[:space:]]+/, ""); print; next } { print }' \
  slides.md > .slides_new.md && mv .slides_new.md slides.md
diff <(tr -d '[:space:]' < /tmp/slides.md.before_fix) <(tr -d '[:space:]' < slides.md)
```
Output: `OK: content identical (whitespace-only change)` — 473 → 456 lines at that point (17 blank lines inside the wrapper collapsed); no line with >= 2 leading spaces before a `<` remains.

### 4.3 Unexpected second bug surfaced by the fix: Vite asset resolution
First `pnpm exec slidev build` after the de-indent **failed**:
```
✗ Build failed in 1.45s
Build failed with 4 errors:
[UNRESOLVED_IMPORT] Could not resolve '/nam_overview.png' in slides.md__slidev_1.md
[UNRESOLVED_IMPORT] Could not resolve '/aop_mini.png' in slides.md__slidev_1.md
[UNRESOLVED_IMPORT] Could not resolve '/physiological_map.png' in slides.md__slidev_1.md
[UNRESOLVED_IMPORT] Could not resolve '/csd_center.png' in slides.md__slidev_1.md

```
Root cause: while the markup sat inside an indented code block, Vite never saw the `<img>` tags. Once the HTML is real markup, a **static** `src="/x.png"` is treated as a build-time asset import, and those four PNGs do not exist (only `*.svg` placeholders). Fix: the four `<img>` now use a Vue binding `:src="'/x.png'"` (not statically analysable → build clean) while `onerror` still falls back to the SVG placeholder. `reaction_diffusion.gif` exists, so it keeps a static `src`.
